# Aeron: build, break, diagnose, recover

tiers: [T0, T1, T2, T3]

Grain: given supplied starters and fault fixtures, build a sequenced service and explain its acceptance, recording, commit, application and acknowledgement boundaries. Four organizing ideas: ownership/flow control; positions/persistence; ordered deterministic state; acknowledgement/recovery. Prerequisites: C++17, processes and basic networking; novice Java is supported by the L01 primer. Retention target: usable a month after first exposure, then recurring project use. This is a design target, not a measured learning outcome. 

Time cost: setup about 5 minutes; eight core lesson headers total 403 minutes (63, 48, 47, 49, 48, 50, 48, 50); one pass through the 35 reviewable cards totals 166 minutes; required delayed assessment totals 107 minutes. The resulting 681-minute card-based planning minimum is about 11 hours over about six weeks. Lesson 1 includes its primer. Later reviews, misses, repairs and optional operations add time. Novice timing has not been measured.

Lessons use `### CARD L01-P0 · Plain label` and `### CONCEPT L01-JAVA · Plain label`. The stable ID is the only machine field in a lesson heading. `manifest/cards.json` has one row per ID with kind, type, topic, objective, minutes, assessment role, grading mode, source, accept and reject predicates, and concept link. The driver and verifier require an exact match between lesson headings and rows. `manifest/claims.tsv` holds one source and verification row per recorded claim or story. Neither manifest is learner reading.

For the learner with the stated prerequisites, each objective has the condition “given the supplied starter and fault fixture,” the following observable behavior, and the criterion “all named checks pass on submitted work, with an explanation meeting every key bullet.” 

| Lesson | Observable behavior | Binary production check |
|---|---|---|
| L01 | Resolve claim ownership and all exit paths; preserve exact bytes | checks/chk_l01_ipc.sh |
| L02 | Retain rejected payloads with bounded retry; reassemble complete bytes | checks/chk_l02_udp.sh |
| L03 | Identify gap, consumption lag or stale duty; repair and drain | checks/chk_l03_diag.sh |
| L04 | Discover recording identity/range; replay exact bytes and reject bad offsets | checks/chk_l04_archive.sh |
| L05 | Remove unlogged inputs; match replica/replay state at a shared barrier | checks/chk_l05_cluster.sh |
| L06 | Reconcile requests across lost replies/failover with at most one mutation per valid key | checks/chk_l06_failover.sh |
| L07 | Restore all application state; replay suffix, reconcile old keys and reject bad snapshots | checks/chk_l07_snapshot.sh |
| L08 | Preserve a fictional course frame, reject adverse tapes and justify guarantee boundaries | checks/chk_l08_sequencer.sh |



T0 uses folded keys and honest bullet self-assessment; `STUDY.md`, generated by `python3 -B drive.py lessons --print-t0` and checked by the tests and verifier, is the single-file T0 edition with keys at the end; T1 adds deterministic scheduling and executable workspace checks, with delayed lab attempts graded on a fresh copy of each card's scaffold. T2 requests optional Haiku advice with fallback; T3 variants remain anchored to existing keys and do not replace required checks. No API key is required for the offline path.   

First exposure days: 1,4,8,11,15,18,22,25. Review introduced cards first at +1 day; successful delayed reviews use +3,+7,+14-day gaps. Misses, partials and low confidence return tomorrow. Keep overdue work. In a session, cap reviews at five estimated minutes, then resume new material while leaving other reviews due; a missed card returns no sooner than the next day. The mixed exam opens at least seven days after final first exposure and completion; delayed production and transfer evidence are required. The Java prerequisite and L02 retry/framing components have separate assessment roles. Exact per-card roles and budgets are in `manifest/objectives.tsv` and `manifest/schedule.json`.   

State has one authority: the learner-selected `--progress` file. README.md gives start/resume commands. The portable `manifest/verify.sh` checks structure and local references; runnable lab checks grade submitted work. Review still requires judging whether an explanation follows from its cited source.
