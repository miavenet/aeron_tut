# Aeron: build, break, diagnose, recover

An order can be sent without arriving, recorded without committing, or applied without its reply reaching you. This hands-on Aeron course helps you spot those boundaries, repair the failure, and recall the rule later. Plan for about 11 hours over roughly six weeks, with short sittings and spaced reviews.

This estimate includes the lessons, setup, one pass through scheduled reviews, and the delayed exam. Later reviews, repairs and optional labs add time. Novice timing has not been measured.

## Quick start

```bash
bash tools/setup.sh
python3 drive.py lessons --today "$(date +%F)" --progress progress.json
```

Run the second command again to resume. Setup downloads and verifies the pinned Aeron jar. No AI model, account, or key is needed. After all lessons are complete, the driver shows the exam opening date. On or after that date, run `python3 drive.py lessons --today "$(date +%F)" --progress progress.json --mode exam`; repeat it to resume the exam across sittings. Use the normal command for reviews.

## How a sitting goes

Plan for 20 minutes. Answer the current card before reading its key, then rate your confidence. For a lab card, edit the named workspace, press Enter for the default path or type another path, then write your explanation before the check and key. A miss offers a retry on the same card. Type `:help` for commands, `:status` for your place, `:skip` when you do not know, or `:quit` to pause. EOF also pauses. Blank input also pauses except at a workspace prompt with a default, where Enter selects that default. The progress file keeps your place. Tomorrow, run the same command. Due reviews come first, using a soft five-minute estimated budget, then new cards. The overall time limit can pause a card between saved phases. Lesson 1 is budgeted for about three 20-minute sittings; repairs and reviews can add time. A slow review or lab can use the whole sitting. On a review or exam day, a lab card does not regrade your earlier `work` folder: the driver creates a fresh `labs/lNN/retrieval-CARD-DATE` copy of that card's scaffold (listed in `manifest/schedule.json` under `delayed_check_scaffolds`), names it, and accepts only that folder. Repair it from memory; it stays in place if you pause.

## Requirements and other paths

This course was tested on **macOS with OpenJDK 26.0.1, Bash, Zsh, curl, and shasum**. The self-tests were run on 2026-11-15 under Python 3.14.6 and Python 3.12.2. Other versions and platforms are untested. The pinned jar contains Java 17 class files, so setup requires Java 17 or newer and warns when your JDK differs from the tested version. `java` and `javac` on `PATH` are enough; `JAVA_HOME` is optional. If setup fails, follow its macOS or Linux next step. C++17 and basic process/network ideas are useful background; lesson 1 includes a short Java primer. Lesson 8 uses a small Python adapter. Its repairs require reading functions, indentation, dictionaries and tuple keys; the lesson supplies a short syntax bridge.

For paper mode, open [STUDY.md](STUDY.md): all eight lessons in driver order with every card key moved to a final section, plus the review schedule, the lab scaffold to copy for each delayed lab card, and the exam cards. It is generated by `python3 -B drive.py lessons --print-t0 > STUDY.md`, and the tests fail if it falls out of step with the lessons. You can also work from [lesson 1](lessons/lesson-01.md) directly: cover the key below each question, answer from memory, then check the key. Keep the card ID when you stop. The lesson files contain the teaching content needed for this route.

Each lesson keeps teaching and folded answers. [Card metadata](manifest/cards.json) holds timing, objectives, grading rules and sources; [the claims record](manifest/claims.tsv) records verification for stories and technical claims.

Run `bash manifest/verify.sh --offline-evidence` to check the course structure. Run `python3 drive.py --help` for all driver options. [PROTOCOL.md](PROTOCOL.md) is optional guidance for an AI tutor; the offline driver works without it.

The course adapts Aeron's [BasicAuctionClusteredServiceNode sample](https://github.com/aeron-io/aeron/blob/1.54.1/aeron-samples/src/main/java/io/aeron/samples/cluster/tutorial/BasicAuctionClusteredServiceNode.java) in the lesson 5 and 6 fixtures.
